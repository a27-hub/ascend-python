### 调优参数：`-mt`（并发数）与 `-to`（超时秒）

> 这两个参数**不只**对应 OOM / 单 case 超时；任何"并发过高 → 资源打满"或"用例自身耗时长"的证据都可触发。**op-atk 本地单设备场景下默认不触发**；仅在 xlsx 失败原因命中"保留"项时才调优。

| 参数 | 含义 | 默认 | 何时调整（**本地单设备适用触发条件**，命中任一即可） | 调整方向 |
|------|------|------|--------------------------------------------|----------|
| `-mt <N>` | ATK 内部最大并发任务数（max threads / concurrency） | `100`（仅告知默认） | ① 内存类：xlsx / tee / dmesg 出现 `out of memory` / `OOM` / `OOM Killer` 杀进程 / 显存爆 | **调小**：实操**先设 `5`**，再按 `5` → `3` → `2` → `1` 逐级下调，找到不再 OOM 的最大可用值；值越小并发越少、越省资源，但全量跑变慢 |
| `-to <S>` | 单 case 超时（秒） | `60` | ① xlsx 出现 `timeout` / `Timed out` / `time out` 类 `失败原因`；② tee / 子进程日志反复打 timeout 锚点；③ runtime / 调度类：`runtime timeout` / `wait timeout` / 子进程心跳超时；④ `Watchdog`（非 collective 类，单进程运行时 watchdog）；⑤ 用例为**大 tensor** 正向计算 / **反向**（`backward`）/ 组合算子，单次合理耗时本身就超过默认 60s | **调大**：阶梯 `120` → `180` → `300` → `600`，按用例真实耗时取**最小够用值**；过大会拖长跑全量时间；超过 `600` 仍不够时按 `→ 1200` 继续上调 |

> **判定纪律**：是否需要 `-mt` / `-to` **必须以证据为准**（xlsx 失败原因 / tee 日志锚点 / dmesg / OOM 报错），**不得**因为"快一点"擅自加 `-mt`，也**不得**默认全局加 `-to`；调整时**必须同步记录**当次调整的依据与目标值到 `运行记录.md`。
>
> **`-mt`/`-to` 何时生效**：仅在 op-atk-adapt **第 4 步——失败用例二次调优复跑**叠加；**首跑全量不加**（首跑就是为了暴露真实瓶颈，盲加会掩盖证据）。

### 调优参数记录表（必须落 `运行记录.md`）

> 任何一次叠加 `-mt` / `-to`，都**必须**在 `运行记录.md` 同步贴出下表，作为后续 3.1 / 3.2 / 4 判读时"为什么此次结果可被采信"的证据。

```md
## 调优参数记录

| 参数 | 默认值 | 调优后 | 调整原因（贴 xlsx 失败原因 / tee 锚点 / dmesg 截取） | 证据来源（xlsx 路径或 tee 行号） |
|------|--------|--------|------------------------------------------------|-------------------------------|
| -mt (并发数) | 100  | <填实际值，如 5>  | 例：大 tensor 计算时显存爆 OOM | 例：atk_full_<ts>.log L<行号> 或 xlsx 失败原因列 |
| -to (超时秒) | 60   | <填实际值，如 600> | 例：`runtime timeout` / 反向耗时 / 大 tensor 计算单次超 60s | 例：atk_full_<ts>.log L<行号> 或 xlsx 失败原因列 |
```

> **填写约束**：
>
> - "调整原因"必须是**对应触发证据列里 ① ~ ⑤**的引用（不允许写"为了快一点"/"经验值"/"看起来该这么调"等无证据描述）。
> - "证据来源"必须能在仓内或远端**可被再次定位**（log 路径 + 行号 / xlsx 路径 + 失败原因列）。
> - 一次复跑同时调 `-mt` 与 `-to` 时，两行都必须填；只调一个时另一个写"未改动"。
> - 持续微调（如 `-mt 5 → 3 → 2`）应**追加新行**而不是改旧行，保留调参时间线。
